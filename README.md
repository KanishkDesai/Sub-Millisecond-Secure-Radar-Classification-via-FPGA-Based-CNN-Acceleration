# Sub-Millisecond Secure Radar Classification via FPGA-Based CNN Acceleration

This repository contains a Vivado RTL implementation of a streaming convolutional neural network accelerator for radar classification on a Xilinx 7-series FPGA. The design combines fixed-point CNN inference with an AES-128 datapath and a lightweight activity signal derived from internal execution values.

The project is written in synthesizable Verilog, with XSim testbenches and hexadecimal memory initialization files for CNN weights, biases, and neuron data.

## Design Summary

The inference path is organized as follows:

1. Three signed 16-bit input channels are accepted by `cnn_top`.
2. Each channel feeds a `window_generator`, which produces a 3x3 sliding window.
3. `controller_fsm` schedules 531 windows across four convolution filter batches.
4. `conv_cluster` and `conv_engine` perform the parallel convolution operations.
5. `featuremap_banks` stores convolution results and supplies the dense stage.
6. `dense_top`, `dense_cluster`, `dense_engine`, and `dense_fsm` perform the fully connected calculations.
7. `classifier3` accumulates three class scores, applies the final biases, and emits the selected class ID.
8. `final_top` packages the CNN with AES-128 processing and an `alive` activity output.

The current classifier RTL compares class score 0 against class score 2 and emits a 2-bit result. Any change to the number of classes or the argmax policy must be made in `classifier3.v` and validated with its testbench.

## Security Datapath

`final_top` collects eight 16-bit samples into a 128-bit plaintext block. The block is passed to `aes_128_top` when the input stream has supplied a complete block. The AES key is provided through the 128-bit `aes_key` input. The AES implementation is decomposed into the following RTL modules:

- `aes_128_top.v`
- `aes_key_round.v`
- `aes_key_schedule_unrolled.v`
- `aes_standard_round.v`
- `aes_addroundkey_128.v`
- `aes_subbytes_128.v`
- `aes_shiftrows_128.v`
- `aes_mixcolumns_128.v`

The `alive` output is generated by a 128-bit feedback register that incorporates AES activity, CNN debug data, the neuron checksum, completion state, and the classification result. It is intended as an activity/integrity indicator, not as a replacement for a cryptographic authentication tag.

## Interface

The top-level integration module is `final_top`:

| Signal | Direction | Width | Description |
| --- | --- | ---: | --- |
| `clk` | input | 1 | Synchronous clock |
| `rst_n` | input | 1 | Active-low asynchronous reset for the wrapper and AES path |
| `start` | input | 1 | Starts CNN processing |
| `ready` | input | 1 | Advances the input stream and sample packing |
| `aes_key` | input | 128 | AES-128 key |
| `pixel_ch0` | input | 16 | Signed input channel 0 |
| `pixel_ch1` | input | 16 | Signed input channel 1 |
| `pixel_ch2` | input | 16 | Signed input channel 2 |
| `done` | output | 1 | CNN classification complete |
| `class_id` | output | 2 | Classification result |
| `alive` | output | 1 | Activity/integrity indicator |

The internal CNN interface is exposed by `cnn_top` and includes `debug_out` and `neuron_checksum` for observability.

## Numeric Representation

- Input samples and stored weights use signed 16-bit values.
- Convolution result lanes are signed 38-bit values.
- The packed convolution result bus is 304 bits wide for eight result lanes.
- The dense feature bus is 1024 bits wide and contains 64 signed 16-bit features.
- Dense accumulators and bias values use signed 48-bit values.
- Dense products are shifted right by 15 bits after multiplication.
- CNN parameters are loaded from Verilog hexadecimal memory files with `$readmemh`.

## Target and Constraints

The Vivado project targets:

- Device: `xc7a100tcsg324-3`
- HDL: Verilog
- Simulator: XSim
- Simulator version recorded by the project: 2025.1
- Clock constraint: 9.560 ns period, approximately 104.60 MHz

The clock constraint is located at `CNN_Accelerator_AMD.srcs/constrs_1/new/clock_constraint.xdc`.

## Opening the Project

1. Install AMD Vivado with XSim support.
2. Open `CNN_Accelerator_AMD.xpr` in Vivado.
3. Confirm that the project target part is `xc7a100tcsg324-3`.
4. Confirm that the memory initialization directory is available to the active simulation and synthesis filesets.
5. Run RTL elaboration or synthesis from the Vivado project flow.

The project records absolute paths from the original development workstation in some generated metadata. If Vivado reports missing imported files, remove the stale generated project data and re-add the tracked RTL and memory files through the project sources view.

## Simulation

Available testbenches include:

- `tb_final.v`: integrated CNN, AES, and wrapper behavior
- `tb_cnn_top.v`: CNN pipeline behavior
- `tb_classifier3.v`: dense classifier behavior
- `tb_conv_engine.v`: convolution engine behavior
- `tb_window_generator.v`: sliding-window generation behavior

To run a testbench, select the desired simulation top in Vivado under **Simulation Sources**, then launch **Run Simulation > Run Behavioral Simulation**. The provided `CNN_Accelerator_AMD.sim/sim_1/behav/xsim/tb_final.tcl` script contains the recorded integrated simulation run command, but the `CNN_Accelerator_AMD.sim` directory is generated output and is not required in source control.

## Reproducibility Notes

The repository tracks the Vivado project descriptor, RTL sources, constraints, testbenches, AES sources, and memory initialization inputs. Vivado caches, checkpoints, run products, waveform databases, reports, and generated simulation directories are excluded by `.gitignore` because they are tool-version- and machine-dependent and can be regenerated locally.

The design should be treated as an RTL reference implementation until timing closure, functional equivalence, resource utilization, and end-to-end classification accuracy have been independently reproduced on the target board and Vivado installation.
